# CRISP

A vertical-slice, CQRS-flavoured ASP.NET Core solution: explicit command/query contracts, direct
service injection (no mediator), immutable Core models, minimal-API endpoints with co-located
services, and a React client typed from the server's contracts.

<!--#if (IsTemplateRepository)-->
## Install and create

```bash
dotnet new install CRISP
dotnet new crisp --name MyApp                  # server + React client
dotnet new crisp --name MyApi --frontend none  # API only
```

| Option | Values | Default |
|---|---|---|
| `--frontend` | `react`, `none` | `react` |
| `--include-sample` | `true`, `false` | `true` |
| `--database` | `postgres`, `mysql`, `sqlserver`, `sqlite` | `postgres` |
| `--auth` | `entra`, `none` | `entra` |
| `--aspire` | `true`, `false` | `false` |
| `--skip-restore` | | `false` |
<!--#endif-->

## What you get

```
CRISP/
├── src/
│   ├── CRISP.Core/        contracts: commands, queries, models, validators (infrastructure-free)
│   ├── CRISP.Server/      minimal-API endpoints + co-located services, EF Core, auth, events, storage
│   ├── CRISP.Migrator/    applies EF Core migrations out-of-band (direct or via SSH bastion)
│   └── CRISP.Client/      React 19 + Vite + Tailwind 4 + shadcn; src/api is generated by TypeGen
├── tests/
│   ├── CRISP.Core.Tests/      validators and query contracts (xUnit v3 + Shouldly)
│   └── CRISP.Server.Tests/    unit + integration against the real database via Testcontainers + Respawn
└── .github/workflows/     build, test (with a database service), migrate, and check the client
```

| Concern | How |
|---|---|
| Database | EF Core 10 on PostgreSQL by default (MySQL, SQL Server and SQLite selectable); one `DatabaseProvider` class per provider holds every difference; the server never migrates at startup |
| Authentication | Entra ID JWT bearer **and** API key, selected per request; roles Viewer / Editor / Admin enriched from the Users table |
| Errors | Handlers throw `RejectedException.NotFound(...)` etc.; `GlobalExceptionHandler` maps it to RFC 7807 with the message intact. Framework exceptions map to a status but their message stays development-only |
| Validation | FluentValidation, run by a group-level endpoint filter; route ids are copied onto the command before validation (`RouteIdBinder`) |
| Events | In-process bounded channel + background worker, fresh DI scope per event, retry with backoff |
| Audit | `AuditLogInterceptor` stamps Created/Updated fields and writes per-entity activity rows; `SoftDeleteInterceptor` turns deletes into flags |
| Files | Presigned-URL upload/download against S3-compatible storage; user-scoped scratch keys; `None` provider for local work |
| Headers | OWASP security headers; the SPA Content-Security-Policy is derived from the configured storage origin plus `SecurityHeaders:ConnectSources` |

## The worked example

`Item` is the slice to copy: `src/CRISP.Core/Items/` (contracts + validators),
`src/CRISP.Server/Features/Items/` (one file per operation, endpoint and service together),
`ItemEntity` + `ItemConfiguration`, `ItemEvents` + `ItemRenamedLogger`, and its tests in both test
projects. Adding a feature means copying it and renaming; see `docs/` for the pattern in full.

## Running locally

```bash
<!--#if (UsePostgres)-->
docker run -d --name crisp-postgres -e POSTGRES_PASSWORD=password -e POSTGRES_DB=crisp -p 5432:5432 postgres:16
# src/CRISP.Server/appsettings.Development.json → ConnectionStrings:default = Host=127.0.0.1;Port=5432;Database=crisp;Username=postgres;Password=password;
DATABASE_HOST=127.0.0.1 DATABASE_NAME=crisp DATABASE_USER=postgres DATABASE_PASSWORD=password dotnet run --project src/CRISP.Migrator
<!--#endif-->
<!--#if (UseMySql)-->
docker run -d --name crisp-mysql -e MYSQL_ROOT_PASSWORD=password -e MYSQL_DATABASE=crisp -p 3306:3306 mysql:8.4
# src/CRISP.Server/appsettings.Development.json → ConnectionStrings:default = server=127.0.0.1;port=3306;database=crisp;uid=root;pwd=password;
DATABASE_HOST=127.0.0.1 DATABASE_PORT=3306 DATABASE_NAME=crisp DATABASE_USER=root DATABASE_PASSWORD=password dotnet run --project src/CRISP.Migrator
<!--#endif-->
<!--#if (UseSqlServer)-->
docker run -d --name crisp-sqlserver -e ACCEPT_EULA=Y -e MSSQL_SA_PASSWORD='Password1!' -p 1433:1433 mcr.microsoft.com/mssql/server:2022-latest
# src/CRISP.Server/appsettings.Development.json → ConnectionStrings:default = Server=127.0.0.1,1433;Database=crisp;User Id=sa;Password=Password1!;TrustServerCertificate=true;
DATABASE_HOST=127.0.0.1 DATABASE_PORT=1433 DATABASE_NAME=crisp DATABASE_USER=sa DATABASE_PASSWORD='Password1!' dotnet run --project src/CRISP.Migrator
<!--#endif-->
<!--#if (UseSqlite)-->
# src/CRISP.Server/appsettings.Development.json → ConnectionStrings:default = Data Source=crisp.db
ConnectionStrings__default="Data Source=src/CRISP.Server/crisp.db" dotnet run --project src/CRISP.Migrator
<!--#endif-->
dotnet run --project src/CRISP.Server        # Vite dev server starts through SpaProxy
dotnet test --project tests/CRISP.Server.Tests/CRISP.Server.Tests.csproj   # needs Docker, or the CI connection-string variable
```

## Working on the template itself

This repository is the `dotnet new crisp` template. It is the shape five production applications
converged on, and where their fixes are consolidated. The repository root **is** the template content (`.template.config/template.json`); there is no
mirrored copy to keep in sync. `tests/CRISP.Template.Tests` instantiates every option combination
and builds the result — run it before publishing, and read
`docs/reviews/2026-09-12-production-consolidation.md` for why things are the way they are.

```bash
dotnet test --project tests/CRISP.Template.Tests/CRISP.Template.Tests.csproj
dotnet pack CRISP.Templates.csproj -c Release -o artifacts
```
