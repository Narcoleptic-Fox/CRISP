# Running locally

This is the everyday loop. [Getting started](/getting-started/) walks the same path once with
more explanation; this page is the short form you come back to.

## Prerequisites

- .NET SDK per `global.json`, Node per `src/CRISP.Client/.nvmrc`, Docker
- `DBPASS` set in the shell (`export DBPASS=...` or `$env:DBPASS = '...'`)

## Database

::: tabs

== tab "PostgreSQL"
```bash
docker run -d --name crisp-postgres -e POSTGRES_PASSWORD="$DBPASS" -e POSTGRES_DB=crisp -p 5432:5432 postgres:16
```

== tab "MySQL"
```bash
docker run -d --name crisp-mysql -e MYSQL_ROOT_PASSWORD="$DBPASS" -e MYSQL_DATABASE=crisp -p 3306:3306 mysql:8.4
```

== tab "SQL Server"
```bash
docker run -d --name crisp-sqlserver -e ACCEPT_EULA=Y -e MSSQL_SA_PASSWORD="$DBPASS" -p 1433:1433 mcr.microsoft.com/mssql/server:2022-latest
```

== tab "SQLite"
Nothing to start. The connection string names a file (`crisp.db`) in the server's working directory.
:::

`appsettings.Development.json` already points at `127.0.0.1` on the provider's default port,
database `crisp`, with `Password=${DBPASS}`. If that port is taken, override for the shell:

```bash
export ConnectionStrings__default="Host=127.0.0.1;Port=5433;Database=crisp;Username=postgres;Password=${DBPASS};"
```

::: callout info "A 200 from /healthz does not prove the database is reachable"
The server does not probe the database at startup. The first request that touches it is the
first time a wrong port or password shows. Run the Migrator first; its exit code is the probe.
:::

## Schema

```bash
DATABASE_HOST=127.0.0.1 DATABASE_NAME=crisp DATABASE_USER=postgres DATABASE_PASSWORD=$DBPASS dotnet run --project src/CRISP.Migrator
```

Healthy: `Target 127.0.0.1:5432/crisp: N pending migration(s).` then `Done. N migration(s) applied in
total; latest is <name>.` and exit 0. Details and the bastion path are in [Migrations](/operations/migrations/).

## Server and client

```bash
dotnet run --project src/CRISP.Server
```

| What | Where |
| --- | --- |
| API | `http://localhost:5051` (`https://localhost:7130` with the `https` profile) |
| Client (Vite, started by SpaProxy) | `https://localhost:58733`, opened for you |
| OpenAPI | `http://localhost:5051/openapi/v1.json` (Development only) |
| Health | `/health`, `/healthz` |

The client alone, for front-end work against an already running server:

```bash
cd src/CRISP.Client && npm install && npm run dev
```

`src/api/` is generated by building Core; if the client fails to compile on a fresh clone with
missing `api/*` imports, run `dotnet build src/CRISP.Core` once.

## Aspire

If the solution was generated with `--aspire true`:

```bash
dotnet run --project src/CRISP.AppHost
```

The dashboard URL is printed on start. It runs the database container, the Migrator, the server and
the client, in that order, with the server waiting for the Migrator to complete.
